# Requisitos Funcionais - 03 a 16

**RF03 - Criar a entidade de usuário:** O estudante deverá modelar a entidade de usuário do sistema utilizando os decorators do TypeORM (@Entity, @Column, etc.), contendo, no mínimo: identificador único (id), nome, e-mail (único), senha (armazenada com hash), perfil de acesso (role) e data de criação. Esta é, nesta etapa, a única entidade obrigatória do sistema.  

**RF04 - Implementar a arquitetura MVC em camadas:** A aplicação deverá seguir uma arquitetura organizada em camadas, separando as responsabilidades entre Routes, Middlewares, Controllers, Services, Repositories, Entities, Database e Utils. A estrutura criada deverá estar preparada para receber futuramente os módulos de domínio da clínica.  

**RF05 - Implementar o cadastro de usuários:** O sistema deverá disponibilizar um endpoint (ex: POST /auth/register) que permita o cadastro de um novo usuário, validando: preenchimento dos campos obrigatórios, formato válido do e-mail e e-mail ainda não cadastrado na base (evitando duplicidade). A senha informada nunca deverá ser armazenada ou retornada em texto puro.  

**RF06 - Implementar a criptografia da senha do usuário:** A senha do usuário deverá ser armazenada utilizando um algoritmo de hash (ex.: bcrypt), de forma que não seja possível recuperar a senha original a partir dos dados armazenados no banco.  

**RF07 - Implementar a autenticação de usuários (login):** O sistema deverá disponibilizar um endpoint de login (ex: POST /auth/login) que valide as credenciais do usuário (e-mail e senha) e, em caso de sucesso, retorne um token JWT contendo, no mínimo, o identificador e o perfil do usuário, com tempo de expiração definido. Em caso de credenciais inválidas, a API deverá retornar o status code 401 (Não Autorizado).  

**RF08 - Implementar o middleware de autenticação:** O sistema deverá implementar um middleware responsável por validar o token JWT enviado nas requisições (via header Authorization), impedindo o acesso a rotas protegidas quando o token estiver ausente, inválido ou expirado.  

**RF09 - Implementar a autorização baseada em funções (RBAC):** A aplicação deverá implementar controle de acesso baseado em perfis de usuário (RBAC), contemplando, no mínimo, os perfis: Administrador (acesso completo) e Atendente (acesso operacional restrito). Um middleware deverá verificar o perfil do usuário autenticado e retornar o status code 403 (Proibido) caso não tenha permissão.  

**RF10 - Implementar endpoints de verificação da autenticação/autorização:** O sistema deverá disponibilizar, no mínimo, os seguintes endpoints: GET /users/me (retorna os dados do usuário autenticado a partir do token) e GET /admin/ping (endpoint protegido, acessível apenas pelo perfil Administrador).  

**RF11 - Impedir operações inválidas:** A aplicação deverá validar e tratar situações como: tentativa de cadastro com e-mail já existente, tentativa de login com credenciais inválidas, requisição sem token, token inválido/expirado e usuário sem permissão (RBAC). A API deverá retornar status codes HTTP apropriados (400, 401, 403 ou 409) com mensagens claras.  

**RF12 - Implementar tratamento de erros:** As operações críticas deverão utilizar blocos try/catch e um middleware central de tratamento de erros, garantindo respostas estruturadas em JSON sem interromper a execução do servidor.  

**RF13 - Utilizar programação assíncrona:** Todas as operações envolvendo acesso ao banco de dados deverão utilizar Promises, async/await e tratamento adequado de exceções.  

**RF14 - Utilizar recursos do TypeScript:** O projeto deverá demonstrar o uso de interfaces, classes, decorators, modificadores de acesso, parâmetros e retornos tipados, além de DTOs (Data Transfer Objects).  

**RF15 - Aplicar boas práticas de programação:** Uso de nomes significativos, separação de responsabilidades, reuso de código e princípios de Clean Code e SOLID.  

**RF16 - Documentar o projeto:** Elaborar arquivo README.md contendo descrição do escopo, tecnologias, requisitos, configuração do banco, instrução de execução, arquitetura, rotas/endpoints e perfis de acesso.
